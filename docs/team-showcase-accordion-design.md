# 首页团队分组折叠设计

## 目标

首页 `team-showcase` 使用默认关闭、单组展开的手风琴结构，降低团队人数增长带来的页面高度，同时完整保留现有作者卡片。完整团队页 `/authors/`、作者详情页、CMS 字段和 Pages Functions 不参与此改动。

## 数据与渲染

- 分组顺序优先读取首页 block 的 `content.user_groups`；作者内容中出现的新分组继续追加到末尾。
- 每个非空分组生成一个 `<details>`，分组名称、人数和头像预览均来自该分组的 Hugo 查询结果。
- 摘要栏最多显示 4 个头像；无头像成员使用现有 identicon；其余成员以 `+N` 显示在头像组最右侧、展开箭头左侧。
- 展开区继续使用原有作者卡片结构与响应式列数，不增加额外容器卡片。

## 交互规则

- 初始不设置 `open`，刷新后所有分组均关闭，不持久化展开状态。
- 所有 `<details>` 共享同一个 `name`，支持的浏览器使用原生单开行为；轻量 `toggle` 监听器为旧浏览器补齐同一行为。
- `<summary>` 保留浏览器原生键盘语义，并通过 `aria-controls` 关联内容面板。
- 展开状态通过主题色边框、背景、箭头旋转和约 250ms 的内容过渡表达；`prefers-reduced-motion` 下禁用动画。

## 维护约束

- 新成员只需维护 author frontmatter 的 `user_groups`，人数和头像预览无需手工同步。
- 新分组无需修改模板；如需固定显示顺序，只需把名称加入首页 block 的 `content.user_groups`。
- 空分组不输出；作者卡片字段和链接行为应继续与改造前一致。
